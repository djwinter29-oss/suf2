SUF2 / local firmware tooling

Pack a signed firmware update

Choose an image, set its execution range, then sign a SUF2 package entirely in your browser.

Signed-only release · encryption is not supported

Firmware remains readable. AES-GCM is deferred until a shared, global per-key encryption budget can be enforced across all producers.

No files or keys are uploaded, and no private keys are persisted. Hosted scripts can read the key you provide. For production signing, prefer a reviewed offline CLI or HSM. Clearing inputs is not a guarantee of secure memory erasure.

1 Firmware image

BIN, Intel HEX, or little-endian ELF32/64 ET_EXEC. Input and normalized image are each limited to 16 MiB. ELF uses file-backed PT_LOAD bytes at physical addresses; BSS is ignored.

2 Identity and execution range

The vendor's opaque 16-byte product identifier, matching device policy. This is not an MCU family ID.

Decimal or 0x-prefixed hexadecimal. For HEX/ELF, base must equal the lowest included address, not the entry point. No included bytes will be silently dropped.

Supply both end and fill to permit gaps or trailing fill. End is excluded; fill is exactly two hex digits (00–FF, optionally 0x-prefixed). Without both, image bytes must be contiguous. Overlaps are always rejected.

3 Local signing key

Choose exactly one key source. ECDSA P-256 only, up to 64 KiB; encrypted PEM and SEC1 keys are unsupported. Key inputs and application references are cleared after every packing attempt. The public-key identifier is derived from SHA-256 of the uncompressed public point.

Package ready

Signed, not encrypted. Confirm the product and execution range against your device policy before deployment.
